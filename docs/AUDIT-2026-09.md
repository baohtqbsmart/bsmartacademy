# Production-readiness audit — September 2026

Scope: all modules (people, academics, tuition, attendance, assignments, tests, English,
assessments, online teaching, lesson designer, material library, analytics, parent portal and
communication, reports, AI assistant). No new features; fixes only.

## How it was checked

| Area | Method |
| ---- | ------ |
| RLS, grants, functions, storage | Catalogue queries on the real migrations (PGlite): tables without RLS or policies, anonymous privileges, `SECURITY DEFINER` functions without a fixed `search_path`, bucket settings, every storage policy |
| ID manipulation (IDOR) | `tests/db/idor.test.ts`: for all 18 tables that reference a student, each non-admin account (2 students, a withdrawn student, 2 parents, 3 teachers) may only see rows of students it is entitled to (computed independently of the policies); per-user tables return only the caller's rows; each non-admin sees one profile (their own); anonymous callers read nothing. Verified by deliberately opening two policies (each caught by 8 failing tests) |
| Roles and pages | `tests/db/matrix.test.ts` (every page × super admin, admin, teacher, parent, student), `tests/app/page-guards.test.ts` (every protected page calls its guard) |
| Server Actions | `tests/app/action-guards.test.ts`: all 166 exported actions check the caller (`requirePermission` / `requireUser`), except the three sign-in actions, and all validate input with a schema |
| Per-module rules | the existing per-module suites (RLS, lifecycles, uploads, mutation-tested) |
| Injection, XSS | code review: no raw SQL from the app; the two PostgREST filter strings built from input are sanitised; no `dangerouslySetInnerHTML` except the chart library's static CSS; links from stored data are `https://` or internal-only (checked in the database) |
| Headers, CSP | production build in Edge: headers present, login, charts, designer preview and PDF/PNG export work with no CSP violations |
| Accessibility, mobile | axe-core (WCAG 2 A/AA + best practice) on the public pages and the designer at 1280 px and 390 px; horizontal overflow checks |
| Links | script: every internal link in the app and in SQL-written notification links resolves to an existing route |
| Dependencies | `npm audit`: 0 vulnerabilities |
| Build | `npm run check`: typecheck, lint, all tests, production build |

## Issues found and fixed

| # | Issue | Severity | Fix |
| - | ----- | -------- | --- |
| 1 | Open redirect: `safeRedirectPath` accepted `/\t/evil.test` (browsers drop tabs/newlines, giving `//evil.test`) — reachable through the sign-in `next` parameter and e-mail links | Medium | Rejects whitespace, control characters and backslashes anywhere; tests added |
| 2 | No security headers: pages could be framed (clickjacking), no CSP, no HSTS | Medium | CSP (no plug-ins, no framing, forms to self, media/frames only from self, Supabase and the two video players), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy` (microphone for self only), COOP, HSTS in production, no `X-Powered-By` |
| 3 | Weak password policy: 8 characters, no composition rule; password change without recent sign-in; reset e-mails every second | Medium | `password_requirements = "letters_digits"` (mirrored in the app's form), `secure_password_change = true`, `max_frequency = "60s"`; clear messages for "sign in again" and "weak password" |
| 4 | No rate limit on messages and announcements (a compromised account could flood families with notifications) | Medium | Database triggers: 30 messages per 10 minutes, 30 new conversations per day, 20 announcements per day for teachers; tests added |
| 5 | Cross-site logout: another site could sign users out by linking to `/auth/sign-out` | Low | Cross-site requests (`Sec-Fetch-Site: cross-site`) are refused |
| 6 | Student profile "Grades" and "Materials" tabs still said "not available yet" although both modules exist | Low (dead feature) | Grades show the student's published results with a link to progress; Materials list library items assigned to the student's classes or shared with them; placeholder component removed |
| 7 | Five selects without an accessible name (designer zoom, progress series, move-to-folder, exercise type, saved-comment picker) | Low (a11y, "critical" in axe) | `OptionSelect` takes an `ariaLabel`; set where there is no visible label |
| 8 | Sign-in, forgot-password and set-password pages had no `<h1>` | Low (a11y) | Titles are level-one headings |

## Verified, no change needed

- RLS on every table; at least one policy each; nothing granted to `anon`; all views `security_invoker`; all 39 public `SECURITY DEFINER` functions pin `search_path` and check the caller.
- All buckets private with size and type limits; every storage policy scoped by folder and record; uploads checked by extension, MIME, size, magic bytes and in the database.
- Sign-up and anonymous sign-in disabled; new accounts only by invitation; sign-in errors do not reveal whether an account exists; password reset never reveals it either.
- Server Actions: Next.js checks the Origin (CSRF); route handlers are GET and side-effect free except sign-out (now same-site only).
- Errors: users see short messages; database and provider details are logged server-side only; error and not-found pages exist; one loading boundary covers the app.
- No hard-coded credentials, test accounts or API keys in the code; secrets only in server environment variables; the AI key never reaches browser bundles.

## Remaining risks

- **Not run against a real Supabase project.** All database checks use PGlite with the real migrations and a Supabase shim; storage policies were tested on rows, not real file downloads; Supabase Auth (sign-in, e-mails, rate limits) was never exercised end to end. Before launch: run the suites against a staging project, then sign in as each role.
- **CSP allows inline scripts and styles** (the App Router needs them without per-request nonces). XSS protection therefore rests on React escaping and on never rendering stored HTML, which holds today.
- **Hosted Supabase settings are separate from `config.toml`.** Password rules, e-mail frequency, sign-up off and rate limits must be set again in the production project's dashboard.
- **General request rate limiting** (per IP, per user) for page loads and Server Actions is not implemented in the app; rely on the hosting platform or a WAF. Sign-in, e-mails, AI, messages and announcements are limited.
- **Families can see their child's teachers' phone numbers and e-mails** (a deliberate earlier choice so they can contact teachers). Restrict the columns if teachers' personal numbers should stay private.
- **Contrast of hidden designer items** is intentionally faded in the editor; teachers choose their own colours in designs, which can fail contrast.
- Accessibility was scanned automatically on the pages that render without a database; the signed-in pages were built with labels, landmarks and keyboard support but were not all scanned with a real session.
